Rate limiter in Go with sliding windows

197 tok

Here’s a sliding-window rate limiter that tracks request timestamps per key. It’s safe for concurrent use and evicts old entries lazily on each call.

type Limiter struct {
  mu     sync.Mutex
  window time.Duration
  limit  int
  hits   map[string][]time.Time
}

func (l *Limiter) Allow(key string) bool {
  l.mu.Lock()
  defer l.mu.Unlock()
  now, h := time.Now(), l.hits[key]
  cut := 0
  for cut < len(h) && now.Sub(h[cut]) > l.window {
    cut++
  }
  h = h[cut:]
  if len(h) >= l.limit {
    return false
  }
  l.hits[key] = append(h, now)
  return true
}

Memory grows with the number of distinct keys, so pair it with a periodic sweep if keys are user-supplied.

For distributed setups, swap the map for Redis sorted sets using a ZREMRANGEBYSCORE plus ZCARD pipeline.

A sliding-window log is exact but stores every timestamp. A ring buffer of size limit gives O(1) checks and bounded memory:

type Limiter struct {
  mu  sync.Mutex
  buf []time.Time
  i   int
  win time.Duration
}

func (l *Limiter) Allow() bool {
  l.mu.Lock()
  defer l.mu.Unlock()
  now := time.Now()
  if now.Sub(l.buf[l.i]) < l.win {
    return false
  }
  l.buf[l.i] = now
  l.i = (l.i + 1) % len(l.buf)
  return true
}

This version is per-limiter, not per-key — wrap it in a sync.Map if you need one per client.
