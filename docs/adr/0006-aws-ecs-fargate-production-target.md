# Production runs on AWS ECS Fargate

The web app and the worker run as separate ECS Fargate services behind an Application Load Balancer, with RDS PostgreSQL, node-based ElastiCache Redis, SES for email and ECR for images, provisioned with AWS CDK in TypeScript. We chose this over App Runner, which is closed to new customers and caps requests at 120 seconds, over Lambda and API Gateway, which would force a different queue and streaming design, and over Fly/Render, because AWS is the intended production environment.

**Considered options**: App Runner (closed to new customers since 30 April 2026 and a 120-second request cap, which kills SSE); Lambda + API Gateway (15-minute streams, 30-second default gateway timeouts, and a queue rewrite away from BullMQ); ECS Express Mode (simpler, but it shares an ALB across services and restricts the load-balancer configuration needed for predictable SSE); Fly/Render (lower operational overhead, but not the required AWS target); Fargate + a dedicated ALB (more control, chosen).

**Consequences**: the ALB idle timeout is raised to 4000 seconds and the app sends heartbeats every 15–20 seconds. ElastiCache must be a standard node, not serverless, because BullMQ is incompatible with the serverless cache's eviction policy and idle disconnects. SES production access must be requested before launch, since the sandbox only sends to verified addresses. Local development stays on Docker Compose, so the containers remain the portability boundary. ALB, NAT and two Fargate services impose a fixed monthly floor of roughly $60–120 before model spend. Region, domain, CI/CD and secret rotation are still open.
