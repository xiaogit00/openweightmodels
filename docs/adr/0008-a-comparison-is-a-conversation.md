# A Comparison is a conversation of Turns

A Comparison is a Conversation: an ordered list of Turns, where a Turn is one user message and the assistant reply it elicits from each Model. The author uploads one Conversation together with the Base model's replies, and every Challenger is replayed through the whole Conversation. A one-Turn Comparison is the degenerate case, not a separate kind of post, so the old Prompt-centric model survives only as the first Turn's Prompt, which supplies the Board headline.

The script and the replies are stored separately: a Turn row holds the user message once, and each Model's reply to that Turn is its own Response row. Responses are flat per Model per Turn rather than nested under a per-model parent, which is what gives Retry, Skip and per-Turn status somewhere to live, and what keeps Annotation offsets scoped to a single self-contained markdown string. Annotations therefore attach to a Response for a Turn, not to "a model's answer" as a whole.

**Considered options**: keeping a Comparison as one Prompt and replaying history only as context while comparing the final reply (discards the turn-by-turn comparison that multi-turn exists to show); storing Turns as a JSON array on the Comparison (no referential integrity, and Annotation offsets still need a per-Turn identity); nesting Responses under a per-model parent row (the parent becomes a second source of status truth and every query has to pick a Turn anyway); making multi-turn a distinct post type alongside single-prompt posts (two code paths through creation, Jobs, rendering and the Board for one concept).

**Consequences**: every existing Comparison is migrated to a single-Turn Conversation. Model calls become stateless full-history replays, so a six-Turn Comparison costs six sequential calls per Challenger and re-sends each Turn's prefix; cost grows faster than the Turn count. A failure mid-Replay is the normal failure case: Retry resumes at the failed Turn, and Skip stops the Replay so a reader never sees answers to a conversation that did not happen. Adding a Challenger to a published Comparison now replays every Turn instead of making one call. The Board, search and titles key off the first Turn's Prompt. The number of Turns and the total replayed text are capped at creation, because the Turn count alone does not bound spend.
