# AI Exporter markdown is the canonical Base output format

The Base output is captured from the author's own chat session, so the intake format is whatever their chat UI can export. We accept the markdown produced by the AI Exporter browser extension as the canonical format: a source-URL line, then alternating `# you asked` and `# <vendor> response` sections each with a `message time:` line, separated by horizontal rules, and a `Powered by [AI Exporter]` footer. The form links to the extension and ships a real export as its sample. Detection is lenient — legacy YAML front-matter files and bare markdown still land as a one-Turn Conversation — but every import passes through a confirmation step that shows what was parsed, flags merged or truncated sections, and refuses a Turn whose reply is missing. Imported metadata, including the source chat URL, is stripped and never stored.

**Considered options**: our own documented template with required YAML keys (rejected: every author would have to hand-transform their chat, which is exactly the confusion this replaces); a strict importer that rejects anything not from AI Exporter (rejected: it strands the plain-markdown authors who exist today); pasting raw chat HTML or JSON exports (rejected: vendor-specific, unstable, and full of UI chrome); scraping a shared chat URL (rejected: needs credentials or public links, and breaks the "your own session" provenance).

**Consequences**: the canonical format is owned by a third party, so the parser is pinned by fixtures taken from real exports, and a format change is a compatibility event. The parser must be fence-aware, because both message bodies legitimately contain `---` and `#` headings. The vendor in the response header is a hint for the Base model picker, never an auto-selection — it names a vendor, not a version. A truncated final reply is accepted with a warning rather than blocked, because an interrupted answer is a legitimate moment in a conversation, while a missing reply blocks creation because the Base output cannot be reconstructed. Imported replies are not editable in v1; the file is the source of truth and a broken export should be re-exported.
