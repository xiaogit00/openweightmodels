# Handoff: New comparison: weight classes and community categories

## Overview
This is a delta on the previous handoff (`design_handoff_redesign/README.md`). All of its global rules, tokens and interactions still apply. This update makes three changes:

1. **New comparison · Step 2, Compare against:** people browse models by **weight class**, and each model shows how big it is so they can roughly gauge its size. Chosen direction: **1a: class tabs and memory bars**.
2. **New comparison · Step 3, Details:** people can **find** categories other people have created, and **create** their own when nothing fits.
3. **Board sidebar:** community categories appear under the preset CATEGORIES.

Everything else is unchanged: page layout, Step 1 (apart from the grouping of the "Generated by" menu), effort, the submit row, the "On the Board" preview, and the Comparison screen.

## Files
- `designs/New Comparison.dc.html` has changed: Step 2 and the Step 3 categories.
- `designs/Board.dc.html` has changed: the COMMUNITY category list in the sidebar.
- `designs/Comparison.dc.html`, `Index.dc.html` and `support.js` are unchanged copies, so the links work.
- `tokens.css` is unchanged. No new tokens.
- `data/models_by_weight_class_curated.csv` is the source data for open-weight models.

Open it the same way as before: serve `designs/` and open `New Comparison.dc.html` (`?state=empty|filled`, `?theme=dark|light`) or `Board.dc.html`.

## Implementation order
1. Data: the weight-class field on models (from the CSV) and a categories endpoint (presets + community, with comparison counts, searchable).
2. Shared primitives: the 6-step **size glyph** (it extends the effort glyph), the **memory bar**, and the **combobox** popover.
3. New comparison Step 2: tab bar, class sections, cards, selected chips.
4. New comparison Step 3: category chips, combobox (browse / search / create), and creating new categories on submit.
5. Board: the COMMUNITY list and its toggle.
6. Check both themes and run the interaction checklists at the end of this file.

## Data model
Each open-weight model gets these fields from the CSV:

| Field | CSV column | Use |
|---|---|---|
| `name`, `pub` | Model, Publisher | Card title and subtitle |
| `total`, `active` | Total_Params, Active_Params | Subtitle shows total; the tooltip adds active for MoE models |
| `gb` | Combined_Min_GB | **The size cue.** Memory to run the model at 4-bit |
| `c` (class) | Weight_Class | One of six classes, listed below |

Frontier API models carry no size. They form their own group, `c = frontier`, and keep the current/previous-release split.

`Previous_Weight_Class` is not shown in the UI. It is fine to keep it in the API for future use, such as a "moved up a class" note.

### Weight classes (ordered, fixed)
| Key | Label | Range | Hardware hint | Glyph bars lit |
|---|---|---|---|---|
| `fly` | Fly | ≤ 12 GB | Phone or laptop | 1 |
| `feather` | Feather | 12–24 GB | 16 GB laptop or mid GPU | 2 |
| `light` | Light | ~32 GB | One 24 GB gaming GPU | 3 |
| `middle` | Middle | 64–104 GB | 80 GB GPU or 96 GB Mac | 4 |
| `heavy` | Heavy | 144–272 GB | GPU + large RAM offload | 5 |
| `super-heavy` | Super Heavy | 300 GB+ | Datacenter cluster | 6 |

Ranges and hints are display copy. Get class membership from the data, never by bucketing `gb` on the client.

## Step 2 changes

### Removed / replaced
- The **Weights segmented control** (All / Open weights / Frontier API) is replaced by the **weight-class tab bar**. "Frontier" is one of its tabs.
- The **OPEN WEIGHTS** section is split into one section per weight class.
- Open-weight **previous releases** are dropped. The CSV is now the curated current list. Frontier previous releases stay behind the existing toggle.

### Kept as is
Search, the max of 4 selected, the SELECTED chips, disabled cards at the max, the step-complete marker, "N of 4 selected", the no-match message and the estimate and hint logic. ETA still drives the submit hint.

### Search
- 40px input. Placeholder: "Search by name, publisher or weight class…"
- It matches name, publisher, slug and class label, so typing "heavy" works.
- Search applies **within the active tab**. Tab counts update to show matches.

### Weight-class tab bar
- A track like the segmented control: 3px padding, `--color-surface` background, 1px `neutral-800` border, radius `--r-lg`, 4px gap.
- 8 tabs: **All sizes · Fly · Feather · Light · Middle · Heavy · Super Heavy · Frontier**.
- Grid columns: `repeat(6, minmax(84px,1fr)) minmax(104px,1.35fr) minmax(84px,1fr)`. Track 7 (Super Heavy) is wider so its label fits. Below that width the track scrolls horizontally (`overflow-x: auto; overflow-y: hidden`).
- Each tab is a `role="tab"` button with 8px 8px 7px padding, radius `--r` and left-aligned content stacked with a 6px gap:
  1. **Size glyph**, 13px tall. Six bars, each 3px wide with a 2px gap and 1px radius, at heights 3/5/7/9/11/13px. Bars up to and including the class index are `--color-accent`; the rest are `neutral-600`. The glyph extends the existing effort glyph. "All sizes" uses the `squares-four` icon and "Frontier" uses `cloud`.
  2. Label: 12.5px/500, with an ellipsis if needed.
  3. Sub line: 11px `neutral-400`, nowrap, `"{count} · {range}"`. "All sizes" shows `"{n} models"` and Frontier shows `"{n} · API"`.
- **Active tab:** `neutral-700` background with text-colored label. **Inactive:** transparent background, `neutral-400` label; hover turns the label text-colored.
- Default tab: **All sizes** in the empty state. The prototype's filled state opens on **Light** to demonstrate the active tab.
- Production: store the tab in the URL as `?class=light`.

### Sections
- **All sizes** shows every class section in size order, then Frontier API, then Frontier previous releases if expanded. Choosing a class tab shows only that section. Empty sections are hidden.
- Section header row (10px gap): a 10px mini glyph (2px bars at 75% height), the label (10.5px/500, 0.08em, uppercase, `neutral-300`), then the hint (12px `neutral-400`), e.g. "LIGHT WEIGHT  ~32 GB · One 24 GB gaming GPU".
- Each section's grid stays as before: `auto-fill, minmax(230px,1fr)`, 8px gap.

### Model card (updated)
- Column layout with padding 10px 12px 12px and a 10px gap. Border and selected states are unchanged.
- **Row 1**, unchanged structure: a 28px initials tile, the name (14px/500), the sub line and an 18px check ring.
  - The sub line is now `"{publisher} · {total params} · ~{eta}s"`, e.g. "Alibaba · 27B · ~6s".
  - The native `title` tooltip reads "Qwen3-Coder-Next 80B-A3B · Middle weight · 64 GB to run · 80B total / 3B active".
- **Row 2, memory bar:** a 4px track (`neutral-800`, 2px radius) that grows to fill the row, followed by a label in Space Mono 11px `neutral-300`, right-aligned, min-width 52px: "32 GB" or "1.5 TB".
  - Fill: `neutral-400`, or `--color-accent` when selected.
  - **Fill width uses one global log scale:** `(ln(gb) − ln 3) / (ln 2000 − ln 3)`, clamped to 0–100%. It must be the same scale in every tab so bars stay comparable. Do not normalize per class.
- Frontier cards have no bar. In its place they show "Size undisclosed" (12px `neutral-500`).
- Keep `data-model-weight` (open / frontier) and add `data-weight-class="{key}"`.

## Step 3 · Details: find or create a category
People can find categories other people have created, and create a new one only when nothing fits.

### Chips row
- The six **Featured** presets are unchanged.
- Any other selected category (community or new) appears after the presets as a selected chip (accent-900 background, accent-600 border, accent-200 text) with a trailing 26px **×** (`aria-label="Remove category {name}"`).
  - Newly created categories also carry a **NEW** tag (9px/600, 0.08em, 1px `accent-700` border).
- The label row shows "N selected" on the right.

### Category combobox
- Below the chips: a 36px search field, max-width 420px, with a magnifier and the placeholder "Find more categories, or create one…".
  - When idle and empty it shows the library size on the right ("25 categories", 12px `neutral-500`).
  - Open state: `--color-accent` border.
  - `role="combobox"`, `aria-expanded`, `aria-controls="category-listbox"`, `maxlength=24`.
- **Focus with an empty query = browse.** The popover lists every community category sorted by comparison count; the user's own new categories come first. Header: "BROWSE COMMUNITY CATEGORIES" on the left, "COMPARISONS" on the right.
- **Typing = search.** It matches presets and community categories by substring, ranking prefix matches first and then by count. Presets show a muted "Featured" label. Header: "MATCHING CATEGORIES".
- **Option row:** 34px, with a check slot (an accent-300 check if already selected), the name, and the count (12px `neutral-400`; "New" for ones the user created). Highlight is `neutral-800`. Clicking toggles selection and clears the query.
- **Create row:** shown only when the query has no case-insensitive exact match. It sits below a `neutral-800` rule: `plus` icon, Create “query”, then a muted "New category". Creating selects the category and closes the popover.
  - The cap is **3 new categories per comparison**. At the cap, the create row is replaced by "You can create up to 3 new categories per comparison."
- **Empty results:** "No categories match “q”." The create row still appears below it.
- **Keyboard:** ↑/↓ moves the highlight (wrapping, create row included). **Enter** picks the highlight; the first row is highlighted by default. **Esc** clears the query first, then closes. Options use `mousedown` + `preventDefault` so the input keeps focus. Blur closes.
- Popover: `--color-bg`, radius `--r-lg`, `--shadow-lg`, `pop` animation, max-height 320px with scroll.

### Where categories show up
- **Board sidebar:** a **COMMUNITY** sub-list sits under the preset CATEGORIES. It reuses the existing list buttons and is single-select with the presets.
  - By default it lists only community categories that have at least one comparison. A ghost toggle "All N community categories ▾" / "Show fewer ▴" reveals the rest, with zero-count names in `neutral-500`. This mirrors the Models list.
  - In the prototype, three sample cards were re-tagged (SQL, Translation, Shell) to demonstrate this.
- **Board card and live preview:** the category chip shows the first selected category, whatever its kind.
- **Production:** new categories are created on submit and become searchable for everyone right away. Moderation and merging of near-duplicates ("Front end" vs "Front-end") is a backend concern; the UI only prevents exact case-insensitive duplicates.
- State: `cats[]` (all selected names), `custom[]` (created in this session), `catQ`, `catOpen`, `catHi`. Board: `allCats`.

## State changes
- `weight` ('all' | 'open' | 'frontier') is replaced by **`tab`**: `'all' | 0–5` (class index) | `6` (Frontier). Use string keys in production.
- `showPrev` now applies to Frontier only. Its toggle shows only on the All sizes and Frontier tabs.
- Model IDs in the prototype are slugs of the CSV name (e.g. `qwen3-8-27b`). Use real API IDs in production.

## Accessibility
- Tab bar: `role="tablist"` with `aria-label="Weight class"`. Each tab is `role="tab"` with `aria-selected`. Arrow-key navigation between tabs should follow the codebase's tab primitive.
- Glyphs are `aria-hidden`. The class name is always present as text (tab label, section header, card tooltip).
- Do not use the size bar alone to convey size: the GB label always sits next to it.
- Category combobox: `role="combobox"` + `role="listbox"` / `role="option"` with `aria-selected`. In production, add `aria-activedescendant` pointing at the highlighted option.
- Remove (×) buttons on category chips have explicit `aria-label`s.
