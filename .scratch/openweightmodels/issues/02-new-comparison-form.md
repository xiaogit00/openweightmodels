# 02: Schedule a Comparison from the New Comparison form

**What to build:** An Author can create a Comparison entirely from the New Comparison screen: upload a Base output, confirm the auto-filled Prompt and title, choose the Base model and up to four Challengers, add Categories and Effort, see a live Board card preview, schedule the Job, and land on an author-only Job summary showing the queued Runs.

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

- [x] Drag-and-drop or browse accepts `.md`, `.markdown` and `.txt` up to 1 MB and rejects invalid type, size, encoding or empty body with a specific inline error.
- [x] Prompt auto-fills from YAML front matter and title auto-fills from the sample or filename; both remain editable.
- [x] A front-matter `model:` that matches the Model registry preselects the Base model; an unknown value is ignored with a clear prompt to choose.
- [x] The Base model tile is disabled as a Challenger, all tiles are disabled at four selected, and the counter reads “N of 4 selected”.
- [x] Categories are multi-select from the fixed list; Effort uses Low/Med/High with the specified sublabels.
- [x] The sticky “ON THE BOARD” preview reflects the form state and shows Draft, Generating or Ready.
- [x] Submit is disabled at 45% opacity until a file, Base model and at least one Challenger exist, with helper text explaining what is missing or estimating calls and the slowest ETA.
- [x] A successful schedule navigates to an author-only Job summary listing the queued Runs; an API failure keeps the form intact and shows an inline error.
- [x] A non-author receives 404 for the Job summary.

## Comments

- 2026-10-22 — Implemented. `/new` renders `NewComparisonClient`; `POST /comparisons` redirects to `/comparisons/:id/job`, which renders the author-only `JobSummary`. Live SSE, Retry/Skip and Publish stay in ticket 03.
- Upload validation reuses `validateFileSize`, `decodeUtf8` and `parseMarkdownUpload`, so type, 1 MB limit, NUL/invalid UTF-8, front-matter and empty-body errors are specific and inline. The sample file goes through the same parser.

The effective Challenger cap comes from the same `MAX_CHALLENGERS` env as the API. Selected tiles stay clickable at the cap so the author can deselect; unselected tiles disable, matching the v2 prototype. The empty/over-long Prompt is refused client-side instead of letting the API fall back to the front-matter Prompt.
- Rules live in `packages/core/src/domain/new-comparison.ts` and are covered by 16 tests in `packages/core/test/new-comparison.test.ts` (matching, base/four-challenger disabling, toggle limits, submit readiness/ETA, empty and over-long Prompt).
